Канал одного отчёта безопасности

Панель «Отчёт безопасности» при открытии читает только сохранённый очищенный
отчёт. Фоновое обновление вида не запускает сбор. Кнопка «Сформировать отчёт
безопасности» запускает один фиксированный локальный снимок Windows в рабочем
потоке. Настройки не меняются; сканирование Defender не запускается. Закрытие
панели отменяет её таймеры; начатый снимок завершится по собственному таймауту.

Отчёт содержит только разрешённые скалярные поля: версию/сборку Windows,
последний наблюдаемый установленный KB, состояние и даты Defender, число
известных ему активных угроз, активные профили брандмауэра, состояние
шифрования системного тома и ограниченное наблюдение конфигурации Windows
Backup. У каждого значения есть время UTC, источник и причина отсутствия
данных. Неизвестное сохраняется неизвестным, а старый отчёт помечается явно.

Это не заключение о взломе и не подтверждение безопасности. Последний KB
не доказывает полноту обновлений. Нулевое число угроз не доказывает отсутствие
заражения. Конфигурация резервирования не доказывает успешную копию или
восстановление. Восстановление и все права агентов/расширений не проверяются.
Поэтому отчёт неполный даже при доступности остальных источников.

Отдельный режим приложения security-mcp обслуживает только stdio запустившего
его MCP-клиента. Сам модуль security_mcp.py также запускается как Python-модуль.
Он не добавляет инструментов в общий MCP, не открывает сетевой порт и не
подключает DOT или другую учётную запись автоматически. Отправки телеметрии,
публикации или самостоятельного запроса к модели нет.

Ровно два инструмента:
  collect_security_report({}) — новый фиксированный локальный снимок; возвращает
    только SecurityReport.for_ai() для сохранённого report_id.
  get_security_report({}) — только чтение последнего очищенного отчёта.
  get_security_report({"report_id":"32 строчных шестнадцатеричных символа"}) —
    только тот же последний отчёт, если его идентификатор совпадает.

Здесь нет истории отчётов, произвольного пути, URL, команды, PowerShell-ввода,
списка файлов, выполнения советов, изменения прав, питания компьютера,
запуска службы или подключения аккаунта. Любые дополнительные аргументы
отклоняются. readOnlyHint означает отсутствие изменения состояния защиты;
сбор всё же сохраняет собственный файл отчёта в профиле пользователя.

Входная строка ограничена 16 КиБ в UTF-8, ответ — 96 КиБ. При слишком длинной
строке канал возвращает короткую ошибку и завершает сеанс, не дочитывая её.
Тексты исключений, приватные пути и содержимое неверных запросов в ошибки
не включаются. Успех collect означает локальное сохранение, а не доставку
отчёта удалённому сервису или прочтение помощником.

Это ограничение возможностей конкретного MCP-канала, а не изоляция Windows.
Программа под той же учётной записью может иметь другие права независимо
от этого канала. Он не отменяет уже выданные другому приложению разрешения.
Для отзыва доступа отключите этот MCP у использующего его клиента и завершите
соответствующий процесс security-mcp. Никакой общий системный агент или
постоянная служба для данного канала не требуется.
