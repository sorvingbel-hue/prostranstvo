ПРОСТРАНСТВО LOCAL BETA 0.1.2 — РАБОТА НАД ПРОЕКТОМ

Принятое направление
Разрабатываем и испытываем Windows-приложение локально. Данные — локальные
SQLite/JSON/PNG в учётной записи пользователя. Собственной онлайн-базы, сервера,
облачной регистрации и удалённого административного доступа в этой beta нет.
Codex и Telegram — отдельные добровольные подключения к внешним сервисам.

Структура чистого проекта
src/ — Python, интерфейс, очередь файлов и отдельные модули функций.
native/ — короткие Windows-launcher, уведомления и helper планировщика.
packaging/ — установщик, сборка и зафиксированные зависимости сборки.
docs/ — инструкции и условия хранения данных.
tests/ — проверки на синтетических данных.
build/ — временные результаты; не распространять целиком.
releases/ — только подготовленные установщик, portable и архив исходников.
Рабочие личные данные не входят в проект и в архив исходников.

Воспроизводимая сборка по инструкции (не обещание побитового совпадения)
Нужны Windows x64, Python 3.13.x с tkinter и .NET Framework csc.exe 4.x.
Первая beta собрана CPython 3.13.3, PyInstaller 6.22.3 и .NET Framework 4.x.
Команды PowerShell из корня распакованного проекта:
  python -m venv build\venv
  .\build\venv\Scripts\python.exe -m pip install -r packaging\build-requirements.txt
  .\build\venv\Scripts\python.exe -B -m unittest discover -s tests -v
  .\build\venv\Scripts\python.exe packaging\build_beta.py
Первая установка зависимостей сборки требует интернета. Готовый установщик
зависимости из интернета не скачивает. Не используйте --reuse-runtime после
изменений src/: этот флаг повторно использует предыдущую Python-сборку.

Как работаем дальше
1. Принимаем одно небольшое изменение и критерий его проверки.
2. Изменяем чистый проект; личную действующую установку обновляем отдельно.
3. Запускаем необходимые тесты, собираем пакет, проверяем manifest и SHA-256.
4. На отдельном Windows-профиле/виртуальной машине проверяем чистую установку,
   запуск без Python, обновление, отказ при работающем приложении и удаление
   с сохранением пользовательских данных. Потом — на втором настоящем ПК.
5. Для каждого beta-тестера фиксируем версию, ОС, воспроизведение ошибки
   и результат. Личную историю, переписку и снимки для отчёта не требуем.
6. После успешного пилота отдельно решаем лицензирование продукта, подпись
   установщика, безопасные обновления, поддержку и публичный канал загрузки.
7. Облачный шлюз/учётные записи/HTTP MCP добавляем только если они нужны
   проверенным сценариям. Локальная программа и данные смогут остаться на ПК.

В этой beta подключение Codex использует stdio MCP с фиксированными инструментами.
Работу обычных задач выполняет локальная программа. Для сетевого подключения
ChatGPT или другого сервиса понадобятся отдельные транспорт, авторизация,
изоляция пользователей и проверка поддерживаемого клиентом протокола.
Локальный MCP-конфиг не публикует приложение в каталоге плагинов.

Нельзя обещать будущим покупателям невидимость, обход Windows/антивируса,
гарантированную доставку поверх любого защищённого экрана или знание того,
какой именно человек использовал общую учётную запись. Beta — видимая программа
с явными переключателями сбора; политики пользователя и Windows сохраняются.
