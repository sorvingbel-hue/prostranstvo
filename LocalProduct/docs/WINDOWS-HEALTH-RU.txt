Диагностика Windows и рекомендации ИИ

Компьютер → Диагностика и ИИ показывает ограниченный локальный отчёт:
место на дисках, версию ОС и датированный статус установленной службы.
«Сформировать отчёт» читает эти сведения; эта кнопка не запускает антивирус,
DISM, ремонт, очистку или модель. «Для помощника» показывает пакет для анализа.

Подключённый ChatGPT/Codex может использовать три stdio MCP-инструмента:
collect_maintenance_report, get_maintenance_report, submit_maintenance_advice.
Они формируют отчёт, читают его и сохраняют советы для точного report_id.
Советы помечены непроверенными; они не исполняются как команды. Устаревший
report_id отклоняется. Модуль не получает ключи, не вызывает сетевой API и
не использует детский диалоговый prompt. Автономная модель без клиента не включена.

Пакет для ИИ не включает личные пути, имя компьютера, SID, account службы,
сырой журнал, команды автозапуска, снимки, историю браузера или переписку семьи.
Предупреждение о месте использует эвристические пороги, а не диагноз диска.
Старый завершённый job не подтверждает сегодняшнее выполнение или здоровье ОС.

В домашней установке отдельная SYSTEM-служба поддерживает фиксированные
diagnostics, scan (QuickScan), health (DISM ScanHealth + SFC verifyonly),
repair (DISM RestoreHealth + SFC scannow), cleanup (StartComponentCleanup).
Они запускаются отдельно по конкретному поручению пользователя. Служба
не принимает произвольный shell, путь или текст совета модели. Существующий
маршрут службы проверяет Windows SID/ACL; собственного родительского PIN
для MCP-запроса обслуживания в нём нет. Общая учётная запись не разделяет роли.

Переносимая Local Beta не устанавливает эту службу: статус not_included
означает недоступность её операций, а не успешную диагностику. Отчёты и
помощник при этом доступны. Новые исходники не означают новый установщик.

Ремонт/cleanup не запускают перезагрузку. Флаги review_required/restart_required
нужно оценить по реальному результату. Завершённый QuickScan не равен полной
проверке всех файлов; подпись файла не гарантирует отсутствие уязвимостей.
Массовая чистка реестра, удаление личных файлов, обновление драйверов,
снятие защит и бессрочная автономная оптимизация в этот модуль не входят.

Локальное продолжение обслуживания

maintenance_sequence.py — отдельный явно запускаемый исполнитель для домашней
установки с уже доступной службой. Он привязывается к точному ID существующего
repair, сохраняет его конечную квитанцию, затем однократно запрашивает cleanup
и health. Он не запускает новый repair, не читает советы модели как команды,
не удаляет файлы и не перезагружает ПК. В интерфейсе отдельной кнопки этой
последовательности пока нет. Portable со своей заглушкой остаётся not_included.

Опрос — раз в 30 секунд, предел выполнения — шесть часов. Один общий lock
исключает параллельных исполнителей последовательности. Неизвестная доставка
запроса после сбоя автоматически не повторяется. Ошибка, чужой job, испорченное
состояние или необходимость перезапуска останавливают продолжение. Истечение
таймера останавливает наблюдение, а не принудительно завершает системный DISM.

Квитанции содержат полные локальные результаты службы и не входят в публичный
репозиторий или ограниченный пакет ИИ. completed означает завершение заданных
шагов; это не сертификация отсутствия повреждений, уязвимостей или вирусов.
Живой запуск наблюдения не доказывает, что будущие cleanup и health уже прошли.
После перезагрузки Windows автоматического возобновления этого исполнителя нет.

Границы personal MCP после security review:
Личная служба сохраняет пять фиксированных операций. Новый system_maintenance
MCP разрешает только diagnostics, health и scan; repair/cleanup отклоняются
до обращения к службе. scan может запустить штатное устранение угроз Defender.
Это ограничение одного AI-маршрута, а не новая ACL/граница самой службы.
Процесс того же Windows-владельца по-прежнему может использовать её другой
разрешённый маршрут. Независимое подтверждение внутри службы — отдельная
задача. Уже работающий MCP должен переподключиться, чтобы загрузить новый код.
В portable нет personal SYSTEM-службы или её system_maintenance инструмента.
