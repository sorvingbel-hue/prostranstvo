## Следующие пять пользовательских сценариев

Только при следующем согласованном свободном экране; это план проверки, не
команды к исполнению сейчас. Перед ними сохраняется пользовательская работа.

1. **Загрузить обновлённый контроллер и проверить понятный статус.** Штатно
   открыть актуальную установленную версию, вызвать панель через **S+D+I**.
   Зафиксировать contract2, feature markers и свежий keeper heartbeat; сверить
   экранный статус с наблюдаемым действием на согласованном реальном окне.
   При предупреждении/ошибке нельзя записывать «контроль работает».
2. **Пройти семейный путь Study → доска → одобрение → игра.** На согласованном
   плане отметить дела, отправить; неверный PIN не одобряет и не снимает Study.
   Правильное одобрение выдаёт время один раз, подтверждает прогресс, доска
   корректно закрывается. Проверить реальные Roblox/Minecraft, разрешённые
   приложения и заявленную политику Codex; повтор кнопки не добавляет минут.
3. **Проверить настоящий цикл 60/10.** После игрового часа возвращаются
   ограничения и полезное дело. Через десять минут игра сама не открывается;
   детская заявка тоже не открывает её. После проверки результата родитель
   разрешает ровно следующий час. Полный такой тест занимает **не меньше
   70 минут**; ускоренная фикстура не закрывает этот gate.
4. **Проверить сохранение срока через сон/вход и перезагрузку.** Записать
   deadline и состояние до/после, сначала для Study, затем для игры/перерыва.
   Новый вход не начинает срок заново, просроченное разрешение не оживает,
   старое подтверждение не завершает новую сессию. Зафиксировать наблюдения
   отдельно для sleep, sign-in и reboot, а не одной отметкой «рестарт прошёл».
5. **Пройти файловый сценарий через установленный интерфейс.** На нескольких
   заранее выделенных собственных тестовых файлах: план → подтверждение →
   перенос → квитанция → проверка → поддержанный обратный перенос. Затем
   открыть анализ выбранного поддержанного кэша: частичность анализа и ошибки
   исполнения видны отдельно. Реальное удаление кэша отмечать выполненным
   только после отдельного наблюдаемого исполнения, не по fake deleter.

Для каждого gate сохранить версию/маркер загруженного кода, условия, шаги,
ожидаемое и наблюдаемое поведение, квитанцию и **PASS / FAIL / NOT RUN**.
Одно окно свободного экрана не обязывает выполнять все пять подряд.
