Место на дисках — явные локальные задания

Панель StoragePanel не запускает проверку при создании или открытии. Родитель
выбирает C: и/или D: и нажимает «Проверить выбранные диски». Задание конечное;
расписания, службы, автозапуска и автоматического повторного обхода нет.

API для интеграции (LocalProduct/src):

  from storage_tasks import StorageTasks
  tasks = StorageTasks()               # никаких записей или обхода
  tasks.status()                      # последнее задание либо state=idle
  tasks.start(["C:\\", "D:\\"])        # только явно выбранные корни
  tasks.status(task_id)                # только UUID в виде 32 hex-символов
  tasks.worker(task_id)                # собственный отдельный процесс

start принимает только корни. Исполняемый файл, команду, shell, каталог отчёта
и имя выходного файла через этот API передать нельзя. Проверяются существующие
каталоги, правила StorageAudit для локальных C:/D:, перекрывающиеся корни,
облачные пути и опасные атрибуты. Статус не перечитывает исходные каталоги.

Обычный исходный запуск использует только собственный storage_tasks.py:
  sys.executable -B <собственный storage_tasks.py> --worker <UUID>

Замороженный запуск использует только собственный exe:
  sys.executable storage-worker --task-id <UUID>

В local_main требуется фиксированный диспетчер:
  from storage_tasks import main as storage_main
  return storage_main(["--worker", args.task_id])

main возвращает 0 для completed/partial и 1 для остальных исходов. Рабочий
процесс создаётся без окна, с приоритетом BELOW_NORMAL, без shell и без
повышения прав. Для замороженной сборки установленный Python не требуется.
Параметр конструктора root предназначен для изолированных локальных тестов;
он не передаётся дочернему процессу, а start для нестандартного root запрещён.

Данные записываются только в собственный каталог на C:, вне распознанных
облачных корней:
  %LOCALAPPDATA%\ProstranstvoLocalBeta\data\storage-tasks\
    tasks.lock, worker.lock, last.json
    jobs\<UUID>\task.json, progress.json, report.json

Намерение queued записывается атомарно до запуска процесса. queued не означает,
что обход уже начался. Только рабочий процесс, получивший общий профильный
exclusive_lock, записывает running и PID. Он держит эту блокировку весь обход.
Второй обход получает busy. Сканирование выполняет существующий StorageAudit;
нового сканера, базы данных или индекса файлов не добавлено.

Состояния: idle, queued, running, completed, partial, interrupted, failed,
busy, uncertain. Неточное состояние запуска и истечение 60 секунд без захвата
задания дают uncertain; автоматического повтора или убийства процесса нет.
Если процесс исчез до фиксации результата, статус даёт interrupted. Даже
progress.json со словом completed не заменяет завершённую запись task.json.
Задержка прогресса более 30 секунд помечается отдельно: файловая операция
может зависнуть, поэтому одно отсутствие обновления не доказывает остановку.

status возвращает task_id, state, roots, временные метки, error_code, progress,
report и точный локальный report_path. Отчёт читается лишь из каталога данного
задания, с ограничением размера и проверкой соответствия корней, времени,
состояния и пути. Нечитаемый или связанный hardlink отчёт не показывается как
успешное завершение. Сохранено не более 256 каталогов заданий; при достижении
предела запуск отказывается с job_limit_reached. Автоматического удаления нет.

UI:
  from storage_ui import StoragePanel
  panel = StoragePanel(parent)
  panel.start_polling()    # только фоновое чтение последнего статуса
  panel.close()            # отменяет Tk-таймеры; рабочий процесс не останавливает

Создание задания и чтение отчёта выполняются в коротком фоновом Python-потоке,
обход — в отдельном процессе. Потоки передают результат через Queue и не
вызывают Tk API. Закрытие/повторное открытие панели не повторяет обход.
Панель показывает до 15 крупных папок и файлов; полный ограниченный отчёт
остаётся локально. Доли выполнения и прогноз освобождения места не выдумываются.

Ограничения: размеры логические, а не физически занятые или освобождаемые байты.
Итоги папок разных уровней пересекаются. Пропуски, отказ в доступе, неизвестная
идентичность файлов и лимиты отчёта видны отдельно; полный объём содержимого
пропущенных каталогов неизвестен. Это живая метадата, не атомарный снимок диска.
Действуют ограничения распознавания облачных путей существующего StorageAudit.
Содержимое файлов, хеши, сеть, перемещение и удаление пользовательских данных
не используются. Отчёты содержат частные локальные пути и не отправляются наружу.

Проверки: изолированные временные каталоги, поддельный backend метаданных,
настоящий временный дочерний процесс для проверки блокировки и mock-виджеты.
Эти тесты не выполняют полный обход реальных C:/D:, ввод в Windows или сеть.
