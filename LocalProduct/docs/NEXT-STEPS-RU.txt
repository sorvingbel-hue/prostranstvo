ПРОСТРАНСТВО — СЛЕДУЮЩИЕ ПРОВЕРКИ И ПРЕДЛОЖЕНИЕ ФУНКЦИИ

Это рабочий план. В beta 0.1.5 реализованы первые версии ручных правил,
настройки папок и архивов. Их полезность для рынка ещё надо проверить.
Разработка и хранение данных остаются
локальными; собственную онлайн-базу не создаём.

ЧТО УЖЕ ПРОВЕРЯЛОСЬ В BETA 0.1.0
Пакет и SHA-256, установка в отдельную тестовую папку, запуск со встроенным
Python без Python в PATH, открытие/закрытие интерфейса, stdio MCP,
обновление с сохранением данных. Жизненный цикл установщика проверялся
с искусственным helper. Это не равно чистой Windows или второму ПК.

ОЧЕРЕДЬ ДО БОЛЕЕ ШИРОКОЙ BETA
1. Аварийные границы переноса и восстановления: остановка процесса,
   отмена, заблокированный файл, нехватка места, коллизия, изменение файла.
   Восстановление должно сверять факт на диске и квитанции, сохранять
   файлы и предлагать проверяемый обратный план без автоматического повтора.
2. Чистая Windows без установленного Python, новый пользователь, кириллица
   и пробелы в путях, установка/обновление/удаление с сохранением данных.
   Проверить установленную и portable-версию, отказ при открытом приложении.
3. Видимая настройка разрешённых папок, включая D, и понятное сообщение,
   если Документы перенаправлены в OneDrive и защищены текущей политикой.
   Интерфейс изменения списка добавлен в 0.1.5; нужна приёмка на втором ПК.
4. Автозапуск и расписания после выхода/входа Windows, сна и блокировки,
   независимые переключатели, отсутствие двойного запуска, мало места.
   Проверки проводить в отдельном тестовом профиле и затем удалять записи.
5. Telegram с отдельным тестовым ботом: фактический обмен в обе стороны,
   обрыв сети, неопределённый результат отправки, перепривязка получателя.
   Не считать принятие API доказательством показа уведомления/прочтения.
6. Нагрузка и удобство: замер старта/CPU/RAM в покое и во время больших
   заданий, много файлов, масштаб Windows 125/150/200%, небольшой экран,
   клавиатура, понятные ошибки и путь к журналам. Пороговые значения
   принять после замера на нескольких ПК; не обещать идеальную скорость.
7. Для публичной продажи: подпись издателя, проверяемые обновления,
   лицензирование/приватность, версия данных и поддержка. Полные ROOT/SYSTEM
   права для обычной установки не нужны; скрытность не является целью.

ГЛАВНАЯ ФУНКЦИЯ ДЛЯ ПРОВЕРКИ — «НАУЧИ ОДИН РАЗ»
Пользователь объясняет задачу обычной фразой своему Codex либо выбирает
шаблон. Программа сохраняет строго описанное правило и выполняет его
обычным локальным кодом. Изменение/составление правила через ИИ может
расходовать токены; повторное выполнение готового правила модели не требует.

Пример: «PDF с invoice в имени из Загрузок копируй в Счета. PNG — в Фото.
Сначала покажи мне результат проверки. Ничего не удаляй».

Минимальная первая версия
- Вкладка «Мои правила»: источник, назначения, простые условия по имени/
  расширению, действие, лимит файлов и объёма, состояние включено/пауза.
- «Проверить»: точный список будущих действий и причины совпадения.
- «Сохранить правило» и «Запустить снова» через существующую очередь.
- Первые действия — обследование/копирование. Перемещения вводить после
  аварийных тестов. Обратный перенос доступен только поддержанным операциям.
- «Почему так?» — какая версия правила сработала и какие файлы затронула.
- Разрешение привязано к конкретным папкам, действию и лимитам правила.
  Изменённая версия требует пересмотра. Произвольный Python не исполняется.
- После надёжного ручного запуска — отдельное явно включаемое расписание.
  Сейчас обычная очередь выполняется, пока открыто основное окно.

Что нельзя обещать
Один пример не даёт бесплатного понимания содержимого любых документов.
Условие «PDF» не отличает счёт от книги; в MVP используем явные признаки.
«Отменить» не означает вернуть любое изменение Windows или чужой программы.
Работа без токенов относится к локальному выполнению готовых правил.

ДОПОЛНЕНИЕ ПОЛЬЗОВАТЕЛЯ — «АРХИВ С ИНДЕКСОМ»
В beta 0.1.5 добавлены подсказка о нехватке места, ручное предложение
ZIP-копии, локальный индекс и проверяемое восстановление. Оригиналы
сохраняются. Автоматический подбор личных файлов и освобождение места
отложены. Управление остаётся через текущий чат/Codex/Дот и интерфейс.
Текущая инструкция — FILES-RULES-ARCHIVES-RU.txt; расширенный проект —
ARCHIVE-WITH-INDEX-RU.txt.

ПРОВЕРКА ПОЛЕЗНОСТИ ДО МАСШТАБИРОВАНИЯ
Предложить 5–10 добровольным beta-тестерам выбрать одну повторяемую задачу.
Записать локально с их согласия: смогли ли настроить правило, выполняется
ли оно правильно, сколько ручных шагов заменяет и пользуются ли им через
неделю. Счётчик запусков не переводить в выдуманную экономию денег/токенов.
Не отправлять личные файлы и историю разработчику для этих измерений.

Аналоги подтверждают наличие самой категории, но не спрос на наш продукт:
Power Automate умеет запись desktop flows, DropIt — правила для файлов,
Hazel — папки и правила. Наша проверяемая гипотеза — простая связка
разговорного ввода, локального исполнения, объяснения и ограниченного возврата.
